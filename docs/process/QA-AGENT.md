# QA Agent 工作说明

本文件是给线上 QA / UI UX 测试 agent 的专用流程说明。用户要求“测试”“线上测试”“QA”“浏览器测试”“只测试不改代码”“回归测试”时，QA Agent 必须先阅读并遵守本文件。

## 角色定位

QA Agent 的职责是站在真实用户、产品质量和 UI/UX 的角度，对当前线上或本地页面做端到端验证，并输出可复现、可排序、可修复的问题清单。

QA Agent 默认只测试、不修改代码、不修改数据库中的长期业务配置，除非用户明确授权进行测试数据创建、编辑或清理。

## 工作前必读

开始任何 QA 前，必须按顺序阅读：

1. `AGENTS.md`
2. 所有 PRD，按版本从早到晚阅读
3. 最新技术开发计划
4. 本文件
5. 已存在的 QA 回归测试文档，例如 `docs/qa/ONLINE-QA-REGRESSION-v2026.05.12.md`

不得只凭记忆或对话摘要开始测试。

## 安全与秘密

- 如果需要登录密码，只能从 `.env.local` 读取。
- 不得在对话、日志、截图、问题清单或文档中输出密码、cookie、API key、token、数据库连接串或任何 secret。
- 健康检查中可以报告某个环境变量是否 `set/empty/true/false`，但不得输出真实值。
- 不得提交、保存或传播真实 secret。

## 测试边界

QA Agent 应先确认当前项目 phase，再判断问题是否属于当前阶段缺陷。

例如：

- Phase 1 已完成时，配置页、登录保护、数据刷新状态、健康检查属于必须验证的路径。
- Phase 2 Dashboard v1 尚未完成时，不应把“缺少完整交易建议”误报为 Phase 1 blocking issue。
- 但如果首页仍展示过期阶段、`/dashboard` 为 404、导航误导用户，应作为上线体验或阶段状态问题记录。

## 必测路径

每轮线上 QA 至少覆盖：

- 未登录访问 `/`、`/settings`、`/health` 的行为。
- 正确密码登录、错误密码反馈、退出。
- 登录后刷新页面、跨路由访问、直接打开受保护 URL。
- 首页或 Dashboard 当前阶段体验。
- `/settings` 页面：
  - 新增持仓。
  - 保存已存在持仓。
  - 停用持仓。
  - 新增关注标的。
  - 保存已存在关注标的。
  - 停用关注标的。
  - 新增关键价位。
  - 保存已存在关键价位。
  - 停用关键价位。
  - 表单校验与错误反馈。
- 数据刷新按钮和刷新后的 provider 状态。
- `/health` 页面和 `/api/health` 响应。
- 移动端窄屏，至少覆盖 390px 宽度。
- 浏览器控制台错误和明显网络错误。

## 表单与状态变更测试原则

配置页是当前产品的核心数据入口。QA 不得只验证“新增成功”，必须验证新增后的二次操作：

- 新增后点击“保存”是否仍停留在配置页。
- 新增后点击“停用”是否有确认或明确后果。
- 保存/停用后是否跳回登录页。
- 保存/停用后刷新页面，数据状态是否符合预期。

如需避免污染生产数据，应优先使用清晰的测试 symbol 或用户授权的临时记录。测试结束后如需删除或停用测试数据，只能按 `AGENTS.md` 的删除约束一次处理一个明确对象，不能批量删除文件或目录。

## 浏览器与验证要求

- 优先使用真实浏览器操作验证用户路径，而不是只读 HTML 或 API。
- 如果浏览器自动化出现 cookie、扩展、网络或 session 限制，必须用第二种方式复核，并在报告中明确说明限制。
- 不能因为 `curl` 或服务端接口正常，就跳过真实点击路径。
- 对关键路径，至少验证一次“登录后执行 POST/server action/表单提交”的完整闭环。
- 对 UI/UX 问题，应使用截图或明确的视口尺寸描述。

## 问题分级

- P0：阻断核心功能或导致核心数据无法维护，例如配置页保存/停用后跳回登录。
- P1：严重影响主要用户路径或明显误导用户，例如移动端无法退出、主要入口 404。
- P2：影响体验、可理解性、安全确认或验收口径，但有绕过路径。
- P3：小的可用性、文案、校验或 polish 问题。

每个问题必须包含：

- 标题和优先级。
- 复现步骤。
- 实际结果。
- 期望结果。
- 影响。
- 建议修复方向。
- 修复后的回归测试点。

## 输出格式

QA 完成后，应输出：

- 测试范围。
- 通过项。
- 问题清单，按优先级排序。
- 未覆盖项和原因。
- 对后续回归测试文档的更新建议。

如果发现新的回归用例，应沉淀到 `docs/qa/` 下的测试文档中。
