# 线上 QA 回归测试用例

版本：v2026.05.12

适用环境：Production `https://stock-selection-pi.vercel.app`

用途：后续用户要求线上测试、QA、回归测试时，QA Agent 必须覆盖本文档中的测试用例。本文档会随产品阶段演进持续增量更新。

## 测试原则

- 只测试，不做代码改动。
- 需要登录密码时，只能从 `.env.local` 读取，不得泄露。
- 测试前先确认当前 phase，不把尚未进入范围的能力误报为缺陷。
- 配置页测试必须覆盖完整编辑闭环，不得只看页面是否能打开。
- 如果使用生产环境创建测试数据，应使用清晰可识别的测试记录，并在用户授权下逐条停用或清理。

## 环境与访问控制

### TC-001：未登录访问首页

步骤：

1. 清理或退出当前 session。
2. 打开 `/`。

期望：

- 未登录时进入登录页，或按当前访问控制设计展示登录入口。
- 不显示受保护数据。

### TC-002：错误密码反馈

步骤：

1. 打开 `/login`。
2. 输入错误密码。
3. 提交。

期望：

- 停留在登录页。
- 显示清晰错误文案，例如“密码不正确”。
- 不泄露 secret 或内部错误。

### TC-003：正确密码登录

步骤：

1. 从 `.env.local` 读取 `APP_ACCESS_PASSWORD`。
2. 打开 `/login`。
3. 输入正确密码并提交。

期望：

- 登录成功。
- 进入应用页面。
- 页面展示受保护导航。

### TC-004：登录 session 持久性

步骤：

1. 登录成功。
2. 刷新当前页面。
3. 直接打开 `/settings`。
4. 直接打开 `/health`。

期望：

- 不应无故回到 `/login`。
- 如果 session 失效，应有明确提示。

### TC-005：未登录访问受保护页保留 next

步骤：

1. 未登录状态直接访问 `/settings`。
2. 在登录页输入正确密码。

期望：

- 登录后回到 `/settings`。
- 不应固定回到 `/`。

### TC-006：退出

步骤：

1. 登录后点击退出。
2. 再访问 `/settings`。

期望：

- 回到登录页。
- 无法访问受保护内容。

## 首页 / Dashboard 当前阶段

### TC-101：首页阶段文案

步骤：

1. 登录后打开 `/`。

期望：

- 页面阶段文案与 `AGENTS.md` 和最新技术状态一致。
- 当前 Phase 4 Watchlist Opportunity Scan 已完成，不应仍显示 Phase 0、Phase 2 准备阶段或旧 Dashboard v1 作为主状态。

### TC-102：Dashboard 路由

步骤：

1. 登录后直接访问 `/dashboard`。

期望：

- Dashboard 应正常展示。
- 页面应包含今日总判断、宏观状态、今日机会、持仓/关注状态、关键价位提醒和数据状态。
- 数据不足时应显示 unavailable/stale 降级状态，不应崩溃或返回默认 404。

## Settings 配置页

### TC-201：Settings 页面基础展示

步骤：

1. 登录后打开 `/settings`。

期望：

- 显示配置页。
- 显示持仓、关注列表、关键价位、数据刷新状态。
- 不显示 secret。

### TC-202：新增持仓

步骤：

1. 在持仓表单输入一个测试 symbol、名称、类型、持仓类型、成本价、仓位。
2. 点击“添加持仓”。

期望：

- 新增成功。
- 页面仍停留在 `/settings`。
- 新增记录出现在持仓列表。

### TC-203：保存已存在持仓

步骤：

1. 找到一个已存在持仓。
2. 修改仓位、成本价或备注。
3. 点击“保存”。

期望：

- 保存成功。
- 页面仍停留在 `/settings`。
- 不跳回 `/login`。
- 刷新页面后修改仍存在。

### TC-204：停用持仓

步骤：

1. 找到一个测试持仓。
2. 点击“停用”。

期望：

- 停用前有确认，或停用后有明确反馈。
- 页面仍停留在 `/settings`。
- 不跳回 `/login`。
- 停用后记录不再作为 active 持仓展示。

### TC-205：新增关注标的

步骤：

1. 在关注列表表单输入测试 symbol、名称、类型、优先级、主题。
2. 点击“添加关注”。

期望：

- 新增成功。
- 页面仍停留在 `/settings`。
- 新增记录出现在关注列表。

### TC-206：保存已存在关注标的

步骤：

1. 修改已有关注标的的优先级、主题或备注。
2. 点击“保存”。

期望：

- 保存成功。
- 页面仍停留在 `/settings`。
- 不跳回 `/login`。
- 刷新页面后修改仍存在。

### TC-207：停用关注标的

步骤：

1. 对测试关注标的点击“停用”。

期望：

- 停用前有确认，或停用后有明确反馈。
- 页面仍停留在 `/settings`。
- 不跳回 `/login`。

### TC-208：新增关键价位

步骤：

1. 输入测试 symbol、类型、价位类型、价格、币种和备注。
2. 点击“添加价位”。

期望：

- 新增成功。
- 页面仍停留在 `/settings`。
- 新增价位出现在关键价位列表。

### TC-209：保存已存在关键价位

步骤：

1. 修改已有关键价位的价格、类型、币种或备注。
2. 点击“保存”。

期望：

- 保存成功。
- 页面仍停留在 `/settings`。
- 不跳回 `/login`。
- 刷新页面后修改仍存在。

### TC-210：停用关键价位

步骤：

1. 对测试关键价位点击“停用”。

期望：

- 停用前有确认，或停用后有明确反馈。
- 页面仍停留在 `/settings`。
- 不跳回 `/login`。

### TC-211：数字字段校验

步骤：

1. 在成本价或关键价位输入负数。
2. 在优先级输入小于 0 或大于 100 的数字。
3. 提交。

期望：

- 页面显示字段级错误，或浏览器阻止无效输入。
- 不泄露内部异常。
- 不写入无效数据。

## 数据刷新与健康检查

### TC-301：刷新数据

步骤：

1. 登录后进入 `/settings`。
2. 点击“刷新数据”。

期望：

- 页面不崩溃。
- 不跳回 `/login`。
- 刷新后展示批次状态。
- provider 成功、失败、未运行状态可解释。

### TC-302：Provider 状态展示

步骤：

1. 打开 `/settings`。
2. 查看 FMP、CoinGecko、FRED 状态。

期望：

- 显示 provider 名称、API key 是否配置、数据日期、最近抓取、入库行数、最近 run。
- 不泄露 API key。
- CoinGecko 未运行时，应能从配置是否存在 active crypto 标的解释。

### TC-303：健康页面

步骤：

1. 登录后打开 `/health`。
2. 直接请求 `/api/health`。

期望：

- `/api/health` 返回 `status: ok`。
- 数据库连接为 ok。
- 当前阶段所需环境变量为 configured/set/true。
- `OPENAI_API_KEY` 为空不应导致当前阶段失败。

## 移动端 UI

- `Settings`、`Health`、`退出` 均可访问。

### TC-402：390px Settings 表单

步骤：

1. 设置视口为 390px 宽。
2. 打开 `/settings`。
3. 查看持仓、关注、关键价位表单。

期望：

- 字段不溢出。
- 按钮不被遮挡。
- 保存和停用按钮可点击。

## 本轮已知回归重点

后续每次修复后必须优先回归：

- Settings 保存/停用后不能跳回登录。
- Settings 任意 server action 提交后不能出现 `This page couldn’t load`。
- 移动端退出入口必须可见。
- `/dashboard` 不能是默认 404，除非产品文档明确暂不提供且有合理占位。
- 未登录访问受保护路径，登录后应回原路径。
